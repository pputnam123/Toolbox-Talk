Keeping the code working — new way (talks file)

You no longer need to re-download the whole app when you add a talk. Talks now live in a separate small file called talks.json that sits next to the app on GitHub Pages. The phone fetches that file live on every scan.

  1. Make your changes here — add or edit talks and schedule on the Talks / Schedule tabs.
  2. In Settings, use Download talks file (talks.json). It's a tiny file — just your talks and schedule.
  3. On GitHub, go to your Toolbox-Talk repo, click Add file → Upload files, drop in talks.json (same name, same folder as the app file), and commit. It replaces the old talks file.
  4. Scan the posted code — the phone loads the new talks file straight away. The app file and the printed QR code do not change.

You only need “Download this file” (the whole app) again if the app itself changes or you change the company / presenter names in a way you want baked into the app file. Day-to-day talk updates are just the talks file.

Phone updates — talks file (talks.json)

This is the new way to update phones. Your talks and schedule live in a separate small file, talks.json, hosted next to the app. When someone scans the QR code, the phone fetches that file live (bypassing its cache), so a new talk shows up as soon as the new talks file is uploaded — no re-downloading the whole app.

Talks file address the phone will load:
— set the hosted address above first —

  1. Add or edit talks as normal on the Talks and Schedule tabs.
  2. Click Download talks file below — you get one small file named talks.json.
  3. On GitHub, open your Toolbox-Talk repo → Add file → Upload files → drop in talks.json → Commit changes. Keep the name exactly talks.json and put it in the same folder as the app file (the top level of the repo).
  4. Wait about a minute for GitHub Pages to update, then scan the posted QR code. The phone should show the new talk. The printed QR code does not change.

First time only: you need to upload the updated app file once (using “Download this file” below) so the hosted app knows to look for talks.json. After that one upload, day-to-day updates are talks-file only. If the live talks file isn't found yet, the phone falls back to the talks baked into the app file, so nothing breaks in between.
